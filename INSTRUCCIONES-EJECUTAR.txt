OPCIÓN 3: MANUAL (Cualquier SO)
================================================================================

1. Abre terminal/cmd en la carpeta del proyecto

2. Copia archivos de configuración:
   $ cp backend/.env.example backend/.env

   $ docker-compose up -d

4. Espera 2-3 minutos a que arranque todo

5. Verifica el estado:
   $ docker-compose ps
   
   Deberías ver 4 containers:
   - postgres (healthy)
   - backend (up)
   - frontend (up)
   - nginx (up)

6. Accede a: http://localhost:3000

  $ docker-compose logs -f

Reiniciar servicios:

  $ docker-compose down

  $ docker-compose down -v

Ejecutar comando en container:
  $ docker-compose exec backend npm run dev
  $ docker-compose exec frontend npm start

Entrar a la BD:
  $ docker-compose exec postgres psql -U catalogo_user -d catalogo_pro

Ver tablas de la BD:
  $ docker-compose exec postgres psql -U catalogo_user -d catalogo_pro -c "\dt"

Ver usuarios:
  $ docker-compose exec postgres psql -U catalogo_user -d catalogo_pro -c "SELECT * FROM users;"

================================================================================
TROUBLESHOOTING
================================================================================

PROBLEMA: Puerto ya en uso (3000, 3001, 5432)
──────────────────────────────────────────────
Solución:
  Linux/Mac:
    $ lsof -i :3000
    $ kill -9 <PID>
  
  Windows:
    > netstat -ano | findstr :3000
    > taskkill /PID <PID> /F

  O cambiar puertos en docker-compose.yml

PROBLEMA: "Cannot connect to Docker daemon"
────────────────────────────────────────────
Solución:
  - Instala Docker Desktop desde https://www.docker.com/products/docker-desktop
  - En Linux: sudo systemctl start docker
  - En Mac: Abre Docker Desktop desde Applications

PROBLEMA: Frontend muestra "Cannot GET /"
──────────────────────────────────────────
Solución:
  - Espera más tiempo (el build puede tardar)
  - Ver logs: docker-compose logs -f frontend
  - Limpiar y reiniciar: docker-compose down -v && docker-compose up -d

PROBLEMA: Backend no responde en /health
─────────────────────────────────────────
Solución:
  - Ver logs: docker-compose logs -f backend
  - Esperar más tiempo (npm install toma tiempo)
  - Verificar que PostgreSQL está healthy: docker-compose ps

PROBLEMA: Error de BD (PostgreSQL)
──────────────────────────────────
Solución:
  - Verificar que postgres está healthy: docker-compose ps
  - Ver logs: docker-compose logs postgres
  - Si no arranca: docker-compose down -v && docker-compose up -d
  - Esperar a que PostgreSQL esté ready (5-10 segundos)

PROBLEMA: Error de permisos en Linux/Mac
────────────────────────────────────────
Solución:
  - Hacer script ejecutable: chmod +x start.sh
  - Ejecutar con sudo si es necesario: sudo ./start.sh

¿QUÉ SUCEDE AL EJECUTAR?
================================================================================

Cuando ejecutas docker-compose up -d:

1. POSTGRES arranca primero
   - Crea la BD "catalogo_pro"
   - Carga el schema SQL (12 tablas)
   - Carga los datos iniciales (seed)
   - Se demora: 5-10 segundos

2. BACKEND arranca (depende de postgres)
   - npm install (instala dependencias)
   - npm run dev (compila TypeScript y arranca)
   - Se conecta a PostgreSQL
   - Se demora: 30-60 segundos

3. FRONTEND arranca (después de backend)
   - npm install (instala dependencias)
   - npm start (compila React y arranca webpack)
   - Se conecta a backend API
   - Se demora: 45-90 segundos

4. NGINX arranca
   - Actúa como reverse proxy
   - Redirige /api al backend
   - Redirige / al frontend
   - Se demora: 5 segundos

TIEMPO TOTAL: 2-3 minutos desde "docker-compose up -d"
